# 交通术语规范化（Traffic Terminology Normalization）

## 任务

把用户口语化、方言化或模糊的交通表述，映射为准确的标准交通术语，输出中英文术语、定义与必要的消歧说明。核心数据是 `references/colloquial_index.json`（2215 个口语说法 → 866 个标准术语的反向索引，按 ID 前缀分为 8 片，另带 `dialects` 地方言对照层）。

## 数据结构与按需加载

索引为归一化结构，正文只存一份，`index` 只存候选词条 ID：

```json
{
  "stats":   {"total_entries": 866, "total_colloquial": 2215, "ambiguous_colloquial": 13},
  "dialects": {"jiangsu": {"region": "江苏", "entries": {"塞车": {"term": "FLOW-0037"}, "...": "..."} },
               "henan":    {"region": "河南", "entries": {"压车": {"term": "FLOW-0037", "surface": "..."} }}},
  "entries": {"INTX-0002": {"zh": "信号交叉口", "en": "...", "cat": "...", "def": "...",
                            "rel": [], "dis": "仅歧义词条有", "std": "仅标注标准的有",
                            "sf": {"口语说法": "句中改写形式", "...": "..."} }},
  "index":   {"红绿灯路口": ["INTX-0002"]}
}
```

上下文预算紧张时不要整包读入 342 KB 的主索引：先读 `references/slices/manifest.json`（1.3 KB，列出 8 个分片及其领域），再只加载相关领域的 `slices/<前缀>.json`（每片 36–50 KB）。**跨域歧义是真实存在的**——例如「路牌」同时指向 ROAD-0099 与 INTX-0051，「充电桩」指向 FWY-0080 与 SAFE-0107。因此当用户表述的领域不明确，或已加载分片给出的候选不足时，必须回查主索引而不是强行按单一分片作答。

## 领域分类（ID 前缀）

| 前缀 | 领域 | 前缀 | 领域 |
|---|---|---|---|
| ROAD | 道路与基础设施 | TRANSIT | 公共交通 |
| INTX | 交叉口与标志标线 | FWY | 高速公路 |
| SIG | 交通信号控制 | ITS | 智能交通 |
| FLOW | 交通流与拥堵 | SAFE | 交通安全 / 静态交通（停车） |

## 工作流程

1. **识别**：从用户输入中提取所有口语化交通表述（整句中可能含多个，如「早高峰加塞堵死了」含 3 个）。
2. **查索引**：在 `references/colloquial_index.json` 的 `index` 字段中查找该说法（键为口语原文，值为候选词条 **ID 列表**），再用 ID 到 `entries` 取术语正文。索引未命中时，尝试：去掉「了」「的」等助词、地区变体（便道/人行道、马路牙子/路缘石/道牙）、近似表述（堵死了→严重拥堵）。
3. **消歧**：一个说法命中多个词条时，按下方消歧规则结合上下文选择。
4. **输出**：按输出格式给出每个术语的规范结果。
5. **方言识别**：索引的 `dialects` 字段收录地区说法（当前江苏、河南、广东、东北、上海、四川），格式为
   `{方言说法: {term: 词条ID, surface?: 句中改写}}`。用户表述带明显地方色彩时
   （如河南「压车/得劲/电驴」、江浙「塞车/电瓶车/道板」），按对应地区的条目映射到
   标准术语，并在输出里注明「<地区>方言」；拿不准是方言还是口误时按普通口语处理。
   用户没有指定地区时，遇到方言词可列出候选地区并请其确认，不要静默假设。
6. **整句改写**：不要把术语生硬塞回原句。口语是谓词性短语（「堵死了」「撞车了」）而
   术语是名词性短语（「严重拥堵」「道路交通事故」）时，直接替换会产出病句；此时用候选
   词条的 `sf` 字段（句中改写形式，如「堵死了」→「陷入严重拥堵」）替换，或仿照其结构
   补出谓语（「发生……事故」「陷入……拥堵」「实施……管制」）。改写完通读一遍，
   主谓搭配、残留的「了/太/很」等成分要顺手理顺，做不到通顺时给出对照表而不是硬改。

## 消歧规则

按优先级依次判断：

1. **上下文领域优先**：用户在讨论信号配时，「相位」指 SIG-0014 信号相位；讨论路口几何时「渠化」指 INTX-0019。
2. **读索引里的 `disambiguation` 字段**：候选词条对象若带 `disambiguation`，直接按其中的取舍说明结合上下文选定，不要自行猜测。该字段已覆盖语料库全部 13 组歧义口语（一路绿灯、路牌、拖车／叫拖车、走应急车道、超吨位、示警桩、能见度仪、充电桩、公交分担率、吊销驾照、地面地铁）；若候选里没有该字段，说明该说法在本库中不歧义，可直接取唯一候选。
3. **程度词分级**：「堵」类表述按程度映射——「稍微有点堵」→ FLOW-0042 轻度拥堵；
   「有点堵 / 走得慢」→ FLOW-0041 中度拥堵；「堵死了 / 堵成停车场」→ FLOW-0040 严重拥堵；
   「突然堵住 / 没事故也堵」→ FLOW-0039 偶发性拥堵；「天天都堵」→ FLOW-0038 常发性拥堵。
4. **方言归一**：便道＝人行道；马路牙子/道牙＝路缘石；马葫芦盖＝检查井盖；雪糕筒＝锥桶；转盘/大圆盘＝环形交叉口；躺坡＝减速带；口误纠正如「闸道」→匝道、「高速动车」≠高铁。
5. **无法确定时**：列出 2-3 个候选及区分要点，请用户补充语境；不得静默猜测。

## 回退规则（索引未命中）

1. 语义最近邻：将口语说法与已收录词条的 term_zh、colloquial 逐字重叠度比较，取重叠最高者，输出时标注「近似匹配」。
2. 组合拆解：长句拆分为多个子表述分别匹配（如「等灯的时候排队排到下个路口」→ 排队长度 + 交叉口溢出）。
3. 仍无法匹配时明确告知「语料库未收录」，按常识给出建议术语并标注「低置信度」，不要伪装成库内数据。

## 输出格式

对每个转换结果输出：

```
口语表述 → 【标准术语】中文（English）
- 定义：<一句话专业定义>
- 领域：<分类>（ID）
- 关联：<相关术语>（可选）
- 消歧说明：<仅当存在歧义或多候选时给出>
```

整句转换时，先给出原句的术语化改写，再逐项列出映射明细。

## 示例

输入：「早高峰那个红绿灯路口加塞太严重，车根本走不动」

- 术语化改写：早高峰时段，信号交叉口违法变更车道行为多发，导致严重拥堵。
- 「早高峰」→ 早高峰（morning peak），定义：工作日早晨通勤需求集中形成的流量高峰时段。领域：交通流与拥堵（FLOW-0005）
- 「红绿灯路口」→ 信号交叉口（signalized intersection），定义：设有交通信号灯并按配时规则分配通行权的交叉口。领域：交叉口与标志标线（INTX-0002）
- 「加塞」→ 违法变更车道（illegal lane changing），定义：不按规定随意变换车道、影响他车正常行驶的违法行为。领域：交通安全（SAFE-0028）
- 「走不动」→ 严重拥堵（severe congestion），定义：速度显著低于自由流、排队严重甚至停滞的拥堵等级。领域：交通流与拥堵（FLOW-0040）。消歧说明：若语境为突发性，应改为偶发性拥堵（FLOW-0039）。

## 数据维护

- 反向索引由源库 `scripts/build_index.py` 从 `data/*.jsonl` 生成，请勿手工编辑；
- 新增口语说法或词条后需重新生成索引并同步本目录（索引与 `slices/` 分片一并重建）；
- `entries` 中每项含 zh / en / cat / def / rel，歧义词条另有 dis，标注了依据的另有 std，
  带句中改写的另有 sf；顶层 `dialects` 收录地区方言对照；本 Skill 无需源数据文件即可独立工作。
